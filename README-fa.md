# سامانه فرم‌ساز مرکزی دانش‌آموز — HTML + CSS + JavaScript

این پروژه نسخه بازطراحی‌شده فرم‌ساز مدرسه است و ساختار اصلی رابط کاربری آن فقط از **HTML، CSS و JavaScript** تشکیل شده است.

برای اینکه یک فرم‌ساز واقعی بتواند از چند گوشی و لپ‌تاپ به یک فرم و یک دیتابیس مشترک وصل شود، پروژه از **Supabase** به‌عنوان سرویس مرکزی Auth + PostgreSQL + Realtime استفاده می‌کند. بنابراین هیچ PHP، Node.js یا Backend اختصاصی در پروژه وجود ندارد.

## راه‌اندازی

### ۱. ساخت پروژه Supabase

یک پروژه Supabase بسازید.

در بخش Project Settings > API دو مقدار زیر را بردارید:

- Project URL
- Publishable / Anon Key

فقط کلید عمومی پروژه را در Frontend قرار دهید. **هرگز Service Role Key را داخل HTML یا JavaScript قرار ندهید.**

### ۲. اجرای دیتابیس

در SQL Editor سوپابیس، کل فایل زیر را اجرا کنید:

```text
schema.sql
```

این فایل موارد زیر را ایجاد می‌کند:

- profiles
- forms
- form_versions
- responses
- audit_logs
- RLS Policies
- RPC برای انتشار فرم
- RPC برای ثبت عمومی پاسخ
- RPC حذف گروهی پاسخ‌ها
- Realtime

### ۳. ساخت حساب مدیر

در Authentication > Users یک کاربر با Email و Password ایجاد کنید.

سپس UUID همان کاربر را بردارید و در SQL Editor اجرا کنید:

```sql
insert into public.profiles(id, display_name, role)
values ('UUID-USER-HERE', 'مدیر مدرسه', 'admin')
on conflict (id)
do update set
  display_name = excluded.display_name,
  role = 'admin';
```

### ۴. تنظیم Frontend

فایل:

```text
config.js
```

را باز کنید و مقدارها را وارد کنید:

```js
window.APP_CONFIG = Object.freeze({
  SUPABASE_URL: 'https://YOUR-PROJECT.supabase.co',
  SUPABASE_ANON_KEY: 'YOUR-PUBLISHABLE-KEY',
  FORM_SLUG: 'student-registration',
  SCHOOL_NAME: 'دبیرستان نمونه دولتی شهید شیرآقایی بهشهر',
  APP_NAME: 'سامانه ثبت اطلاعات دانش‌آموز',
});
```

### ۵. آپلود

کل پوشه را روی هر هاست Static که HTTPS ارائه می‌کند قرار دهید.

مثلاً:

```text
/index.html
/config.js
/assets/app.js
/assets/styles.css
/schema.sql
/README-fa.md
```

هیچ PHP یا تنظیمات سرور برای اجرای Frontend لازم نیست.

## نحوه کار چنددستگاهی

### روی لپ‌تاپ مدیر

مدیر وارد پنل می‌شود و سؤال‌ها را تغییر می‌دهد.

### ذخیره پیش‌نویس

تغییرات در جدول `forms` روی دیتابیس مرکزی ذخیره می‌شوند.

### انتشار

با کلیک روی «انتشار برای همه دستگاه‌ها»، تابع `publish_form` یک Snapshot جدید در `form_versions` می‌سازد و نسخه قبلی را از حالت Published خارج می‌کند.

### گوشی‌ها

همه گوشی‌ها فقط نسخه Published را دریافت می‌کنند.

### تغییرات هم‌زمان

پنل مدیر از Realtime برای دریافت تغییرات فرم استفاده می‌کند. اگر مدیر روی دو دستگاه باز باشد و یکی تغییرات دستگاه دیگر را ایجاد کند، نسخه سرور تشخیص داده می‌شود و در صورت داشتن تغییر ذخیره‌نشده، پیام Conflict نمایش داده می‌شود.

## نکته مهم درباره داده‌های قبلی

هر پاسخ همراه با `form_version_id` و `schema_snapshot` ذخیره می‌شود.

بنابراین اگر سؤال‌ها بعداً تغییر کنند، پاسخ‌های قدیمی ساختار سؤال‌های زمان ثبت خود را حفظ می‌کنند.

## محدودیت آگاهانه

این پروژه کاملاً HTML/CSS/JS است، اما برای دیتابیس مشترک چنددستگاهی به یک Backend-as-a-Service نیاز دارد. در این نسخه این نقش توسط Supabase انجام می‌شود.

اگر اینترنت قطع شود، فرم عمومی و فرم‌ساز نمی‌توانند داده جدید را در دیتابیس مرکزی ثبت یا دریافت کنند؛ زیرا هدف این معماری، همگام‌سازی واقعی چند دستگاه است.
